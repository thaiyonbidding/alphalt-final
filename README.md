# ระบบตัดสต็อกโรงงานผลิตยางมะตอย v2 (asphalt-stock-v2)

ระบบแยกต่างหากจาก Fuel Approval Bot — ฐานข้อมูลคนละตัว, Railway project คนละตัว
ผ่านการทดสอบ API ครบทุก endpoint แล้ว (production, diesel, receiving, delete-with-restore, settings)

## สรุปพฤติกรรมระบบ (ตามที่ยืนยันกันไว้)

### บันทึกประจำวัน (การผลิต) — `/production`
กรอกครั้งเดียวตอนสิ้นวัน:
- ตันที่ผลิต + อัตราส่วนยางมะตอย (ลิตร/ตัน) → ระบบคำนวณหิน 3 ชนิดอัตโนมัติจากสูตรคงที่ (หน่วยตัน)
  - หินฝุ่น = ตัน × 0.434, หิน 3/4 = ตัน × 0.267, หิน 3/8 = ตัน × 0.300
- ยางมะตอย **แบ่งได้หลายถัง** (4 ถังอิสระ) — เพิ่มแถวได้ถ้าใช้มากกว่า 1 ถัง มีตัวเช็คยอดรวมเทียบกับสูตร
- น้ำมันเตา: กรอกระดับ **ต้นวัน (auto จากสต็อกปัจจุบัน) / สิ้นวัน (manual)** → ตั้งสต็อกเป็นค่าสิ้นวันตรงๆ (ไม่ใช่หักลบสะสม เพราะอ่านจากเกจจริง)
- **ดีเซลไม่เกี่ยวกับฟอร์มนี้เลย**

### สต็อก — `/stock`
- การ์ดแสดงยอดคงเหลือทุกวัสดุ (หิน 3 + ยาง 4 ถัง + น้ำมันเตา + ดีเซล) พร้อมแจ้งเตือนสต็อกต่ำ
- ดาวน์โหลดรูปสรุปสต็อกได้ (Canvas วาดเอง ไม่พึ่งไลบรารีนอก)
- **การ์ดบันทึกน้ำมันดีเซล** (แยกจากการผลิต ใช้กับรถสิบล้อ): กรอกเลขไมล์ตู้จ่าย ต้นวัน (auto, แก้ไขได้) / สิ้นวัน (manual) — เลขนี้**เพิ่มขึ้นเรื่อยๆ** ต่างจากน้ำมันเตา → ใช้ไป = สิ้นวัน − ต้นวัน หักออกจากสต็อกดีเซลจริง
- ประวัติการผลิต + ประวัติดีเซล **ลบรายการได้ พร้อมคืนสต็อกอัตโนมัติ**

### นำเข้าวัสดุ — `/import`
- **ไม่ต้องใส่ PIN**
- เลือกวัสดุ + จำนวน + บริษัทผู้ขาย (ดรอปดาวน์ เพิ่มใหม่ได้ทันที) + ทะเบียนรถ (เหมือนกัน)
- ประวัติการนำเข้า ลบได้ (ปรับสต็อกกลับอัตโนมัติ) + ดาวน์โหลดรูปสรุปการนำเข้าได้

### ตั้งค่า — `/settings`
- ยังคงต้องใส่ PIN (ตั้งต้น `1234`)
- ปรับสต็อกด้วยมือ (ใช้ตั้งสต็อกเริ่มต้นได้), แก้สูตร/เกณฑ์แจ้งเตือน, เปลี่ยน PIN

## ขั้นตอน Deploy

### 1. อัปโหลดขึ้น GitHub
สร้าง repo ใหม่ เช่น `asphalt-stock-v2` ที่ https://github.com/thaiyonbidding

⚠️ **สำคัญ**: ลากไฟล์/โฟลเดอร์ **ข้างในของ asphalt-stock-v2** (server.js, package.json, public/, db/ ฯลฯ) ขึ้นไปที่ root ของ repo โดยตรง **อย่าลากทั้งโฟลเดอร์**

### 2. สร้าง Railway Project ใหม่
- New Project → Deploy from GitHub repo
- Add → Database → PostgreSQL (จะได้ `DATABASE_URL` อัตโนมัติถ้าอยู่ project เดียวกัน)
- Settings → Networking → Generate Domain

### 3. ตรวจสอบ
เปิด `https://xxxx.up.railway.app/health` ต้องเห็น `{"status":"ok"}`
เช็คผ่าน DevTools → Network (Disable cache) เพื่อความชัวร์

### 4. ตั้งสต็อกเริ่มต้น
ไปที่ `/settings` → PIN `1234` → "ปรับสต็อกด้วยมือ" → ใส่ยอดจริงทีละวัสดุ (หิน 3, ยาง 4 ถัง, น้ำมันเตา, ดีเซล)

## โครงสร้างไฟล์
```
asphalt-stock-v2/
  server.js              Express server + API ทั้งหมด
  package.json
  .env.example
  db/
    schema.sql            สร้างตารางอัตโนมัติตอน server เริ่มทำงาน
  public/
    shared.js              helper กลาง (format ตัวเลข, toast, canvas export, nav)
    production.html        บันทึกประจำวัน
    stock.html              สต็อก + บันทึกดีเซล + ประวัติ
    import.html             นำเข้าวัสดุ (ไม่ต้อง PIN)
    settings.html           ตั้งค่า (PIN protected)
    style.css
```

## ตาราง Database หลัก
- `materials` — สต็อกปัจจุบันของทั้ง 9 รายการ (หิน 3, ยาง 4 ถัง, น้ำมันเตา, ดีเซล)
- `production_logs` — เก็บ tank_splits เป็น JSONB เพื่อคืนสต็อกได้ตรงตอนลบ
- `diesel_logs` — เลขไมล์ต้นวัน/สิ้นวัน แยกจาก production_logs
- `companies`, `vehicle_plates` — auto-insert เวลานำเข้า หรือเพิ่มเองผ่านหน้านำเข้า
- `stock_receiving`, `stock_adjustments` — ประวัติ + audit trail

## หมายเหตุทางเทคนิค
- ทดสอบ API ครบทุก endpoint แล้วในเครื่อง (Postgres จริง) ก่อนส่งมอบ — คำนวณสูตร, ตัด/คืนสต็อก, ลบรายการ ตรงตามสเปคทุกจุด
- ตารางฐานข้อมูลสร้างอัตโนมัติทุกครั้งที่ server เริ่มทำงาน (`CREATE TABLE IF NOT EXISTS`)
- ไม่ต้องตั้งค่า `RAILPACK_DEPLOY_APT_PACKAGES` เพราะไม่มีการสร้าง PNG/ฟอนต์ไทยเหมือน Fuel Bot
- ช่องตัวเลขทั้งหมดใช้ `type="text" inputmode="decimal"` แทน `type="number"` เพื่อความเข้ากันได้กับคีย์บอร์ดมือถือไทยบางรุ่น
